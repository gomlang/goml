# csv

Streaming CSV readers and writers implemented in GoML over `std::io::Read` and
`Write`, with raw byte records, UTF-8 records and explicit Serde row schemas.
There are no native adapters or runtime dependencies outside the standard
library. Quoted records are parsed by a byte state machine across arbitrary
input boundaries; embedded newlines never become independent records.

```goml
use ecosystem::csv;
use std::bytes;
use std::io;
use std::serde::{Deserialize, Serialize};
use std::utf8;

#[derive(Deserialize, Serialize)]
struct Person {
    name: string,
    age: u8,
}

fn example() -> Result[(), csv::Error] {
    let schema = csv::Schema::new(Vec::from_array([
        csv::Column::new("name", csv::ScalarType::Text),
        csv::Column::new("age", csv::ScalarType::Unsigned(8)),
    ]))?;
    let source = io::Cursor::new(bytes::Bytes::from_vec(utf8::encode("name,age\r\nAda,37\r\n")));
    let reader = csv::Reader::new(source, csv::ReadOptions {
        headers: true,
        ..csv::ReadOptions::new()
    })?;
    let output = io::Cursor::new(bytes::Bytes::new());
    let writer = csv::Writer::new(output, csv::WriteOptions {
        headers: true,
        ..csv::WriteOptions::new()
    })?;
    while let Some(person) = reader.decode_next::[Person](schema)? {
        writer.serialize(person, schema)?;
    }
    writer.flush()
}
```

## Record and dialect APIs

`Reader::next_bytes()` returns `Result[Option[ByteRecord], Error]` without
requiring UTF-8. `next()` returns a `StringRecord`, and `decode_next[T](schema)`
returns a typed row. `None` is stable EOF. `headers()` lazily reads and caches the
first non-skipped record when header mode is enabled; it does not consume a data
row. Header names must be valid UTF-8 and nonempty.

`ByteRecord::new(Vec[bytes::Bytes])` and `StringRecord::new(Vec[string])` capture
independent values. `len`, `get`, `position` and `field_position` inspect a record;
`ByteRecord::strings` validates text and `StringRecord::bytes` encodes it.
`StringRecord::values()` and byte-field accessors return independent containers.
Keeping or modifying a returned record cannot affect later reads.

`Writer::write(record)` writes a string record and `write_bytes(record)` accepts
raw bytes. `serialize(value, schema)` writes flat Serde structs. `flush()` forwards
to the underlying writer. A single row is encoded and checked before I/O; the
library buffers one bounded row, not the complete table.

| Setting | Read default | Write default |
| --- | --- | --- |
| Delimiter / quote | Comma / double quote | Comma / double quote |
| Terminator | `Any`: CRLF, LF or CR | `CrLf` |
| Strict quoting | Enabled | Necessary quoting |
| Fixed width | Enabled, established by the first record/header | Enabled, established by the first successful record/header |
| Headers | Disabled | Disabled; when enabled, generated by the first typed serialization |
| BOM | Strip one UTF-8 BOM only at stream start | Do not emit |
| Blank records | Preserve as one empty field | A single empty field is quoted |
| Trimming | Disabled | No implicit trimming |
| Read buffer | 8 KiB, configurable from 1 byte to 1 MiB | One bounded encoded record |

Delimiter and quote are distinct ASCII bytes other than CR/LF. `Terminator::Byte`
selects a distinct ASCII record terminator. In that mode, CR/LF are ordinary field
data unless selected as the terminator. `CrLf` requires CRLF between records but
still accepts an unterminated final record. Within quoted fields all terminators
are data. Writer `Terminator::Any` emits LF.

Strict reading rejects quotes in unquoted fields, junk after closing quotes, and
unterminated quoted fields. `strict: false` preserves bare quotes in unquoted
fields, appends trailing junk after a closing quote, and accepts EOF inside a
quoted field. It does not disable size, width or header checks. Strictness governs
CSV structure; byte records may contain arbitrary bytes, including control bytes.

`trim: true` removes ASCII space and tab at decoded field edges, including quoted
fields. It does not permit whitespace before an opening quote or after a closing
quote in strict mode. `skip_blank: true` ignores records with no source field
bytes; quoted empty fields and comma-separated empty fields remain records.

`QuoteStyle::Necessary`, `Always` and `Never` control output. Necessary quoting
handles delimiters, quotes, CR/LF, custom terminators, a sole empty field and a
leading BOM in the first field. The latter preserves actual U+FEFF field content
when read with BOM stripping enabled. Quotes inside quoted fields are doubled.
`Never` rejects a field requiring quotes before emitting any bytes.

## Headers and typed Serde rows

`HeaderPolicy::Reject` rejects duplicate names. `First` and `Last` retain the raw
header record and select the corresponding occurrence during typed mapping.
All policies reject empty names. Without headers, schema columns map by position;
with headers, they map by exact case-sensitive name and may be reordered.

A `Schema` contains uniquely named `Column` values. Supported types are `Text`,
`Bool`, `Signed(width)`, `Unsigned(width)`, `Float(width)` and `Char`. Integer widths
are 8/16/32/64 or 0 for the platform-sized type; floats are 32/64. Integers preserve
the complete signed and unsigned 64-bit range. Booleans are exactly `true` or
`false`; floats must be finite; chars contain exactly one Unicode scalar. Numeric
syntax follows `std::num`. Text columns always remain strings, so `0042` is not
silently converted to an integer.

`Column::optional()` maps an empty cell to `None`. A required text column permits
the empty string. CSV has no intrinsic null representation: optional text cannot
distinguish `None` from `Some("")`. Column `trim: true` uses `std::text::trim` before
conversion. The declared schema must agree with the target struct's Serde types.
The row root is a flat struct; nested structs, arrays, maps, binary fields, enums,
unit values and nested optionals are rejected instead of being flattened or
stringified. Scalar fields are converted through the explicit schema.

Unknown headers and extra serialized fields are rejected by default;
`schema.allow_extra(true)` projects the declared columns and ignores extras.
Missing schema columns and header/record width mismatches remain errors. Generic
Serde mismatches are reported at the row start; scalar conversion failures report
the offending field position. Serde rename attributes select the serialized field
names used by the schema.

Automatic writer headers are emitted once, in schema order. Later typed writes
must use the same header names and order. Automatic headers cannot be inserted
after raw writes. Header and first-row size limits are checked together before
either is emitted. Applications can write explicit raw headers with header mode
disabled.

## Positions, I/O and errors

Positions contain a zero-based byte offset and one-based CSV record, physical
line and byte column. Record numbers include headers and skipped blank records;
quoted newlines increase physical line numbers without increasing record numbers.
CRLF counts as one physical newline across read boundaries. BOM bytes contribute
to byte offsets and columns. `field_position` points to the first wire byte of
the field, including an opening quote. UTF-8 failures point to the actual invalid
wire byte, including adjustments for doubled quotes and embedded newlines.

Errors expose their category, position, optional zero-based field index, message
and optional underlying `io::Error`. Parse, header, width, limit and input I/O
errors fuse the reader: later calls return the saved error without consuming more
input. A completed row's UTF-8 or typed conversion error consumes that row and
allows processing the following row. EOF remains `None` without further reads.
In `Any` mode, a completed CR-terminated row is returned before an I/O error from
looking ahead for its optional LF; the saved error is returned on the next call.

Short reads and writes are supported. Every read or write error, including
`Interrupted`, stops the operation without automatic retry and fuses that wrapper. Invalid
transfer counts become errors. A successful zero-byte read is EOF; a zero-byte
write is an error. Writer positions track only bytes confirmed by successful
write calls. A failed call may already have produced side effects, particularly
through `MultiWriter` or `OffsetWriter`; the saved position is not a safe retry
offset or a guarantee that the remaining bytes were never written. Subsequent
writer calls return the saved error without replaying the row or forwarding
flush. Validation errors before output do not poison the writer, so a caller may
correct the row and try again. Flush failures also fuse the writer.

A failed read may already have consumed source bytes or modified its destination
buffer without reporting a count. Those bytes are not parsed, and the saved
reader position reflects only confirmed input, not a safe transport restart
offset. The completed-CR-row lookahead rule above still delivers that row before
returning the saved error. Recovery requires caller-owned transport knowledge;
constructing another reader does not restore consumed input.

Reader and writer aliases serialize operations through an internal gate, including
short transfers, so concurrent calls do not interleave records. The caller owns
the underlying stream and must not independently read/write it while the wrapper
is active. Wrappers do not close streams. Cancellation/deadlines, when needed,
belong to the supplied transport; there is no background task or implicit retry
of a failed row.

## Bounds and verification

`Limits` bounds decoded field bytes, encoded input/output record bytes, columns,
record count and total stream bytes. Defaults are 1 MiB per field, 8 MiB per wire
record, 4,096 columns, 1,000,000 records and 1 GiB total. Record byte limits include
quotes, delimiters and terminators; total byte limits also include the BOM.
Header and skipped blank records count toward record limits. Input may buffer
ahead up to the configured read buffer; an additional byte can be probed to
distinguish exact-limit EOF from an oversized stream.

The reader retains decoded field bytes and bounded wire bytes for precise UTF-8
positions. It does not seek, infer dialects, parse comments, normalize newline
bytes within fields, automatically transcode other character sets, or perform
spreadsheet formula sanitization.

The native GoML suite includes fixed cases from
[RFC 4180 section 2](https://www.rfc-editor.org/rfc/rfc4180.html#section-2),
all chunk sizes for quoted/multiline/Unicode examples, 1,500 generated field-pair
roundtrips across terminators and short writes, error positions, BOM content,
invalid UTF-8, limits, malformed I/O counts, fused failures, type/schema failures,
full-width numbers, Unicode chars and concurrent handle use. The design also
consults [rust-csv's reader API](https://docs.rs/csv/latest/csv/struct.ReaderBuilder.html);
it does not claim identical defaults or permissive parsing behavior.
