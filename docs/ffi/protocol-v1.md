# Go metadata protocol v1

Transport is one JSON request on stdin and one JSON response on stdout. stderr is reserved for operational diagnostics. [The protocol package](../../tools/goml-go-meta/internal/protocol/protocol.go) defines the current wire schema. See the [language guide](../goml.md#go-ffi) for source-level bindings and [bind-go](bind-go.md) for allowlisted generation.

Every request contains `protocol_version: 1`, `build_context`, `caller_context`, and `bindings`. Unknown fields, unknown type tags, duplicate or empty binding IDs, malformed/trailing JSON, and invalid contexts are recoverable `ffi-protocol` errors.

`build_context` explicitly carries `go_executable`, `toolchain`, `module_dir`, `goos`, `goarch`, `cgo_enabled`, `goflags`, `build_tags`, `go111module`, `gowork`, `dependencies`, and `network`. v1 uses `gowork: "off"`, `dependencies: "readonly"`, and `network: "off"`. Module mode is `on` or `off`; cgo is `0` or `1`. These fields are resolved once by project orchestration and reused for analysis and Go compilation. The host helper itself must be built for the host. Paths are JSON strings, preserved without shell interpretation.

`caller_context` carries `load_mode`, `import_path`, `directory`, and `package` of the actual generated caller. Import legality must be checked in that context, including internal-package restrictions and import cycles. `load_mode` is `package` for a directory package or `files` for an explicit Go file list. File mode requires the import identity `command-line-arguments` and loads only the overlay witness files, excluding stale generated output and unrelated files in that directory. A new library target requires its own validation context.

A binding has `binding_id`, `import_path`, `symbol`, `bridge_parameter_types`, `bridge_result_types`, and `call_mode`. The existing `ordinary` mode uses a nonempty `import_path` and a package-level function symbol. The additive `method` mode requires an empty `import_path` and at least one parameter; parameter zero is the receiver, and `symbol` is its method name. The receiver type supplies any package identity. IDs identify declarations independently of Go symbol spelling. Multiple different IDs may request the same Go symbol. Parameter/result arrays describe the actual Go wrapper operation, not GoML surface types. No results means unit; multiple results mean a flat tuple.

Bridge types use these structured nodes:

| Tag | Additional fields |
| --- | --- |
| `bool`, `int`, `int8`, `int16`, `int32`, `int64`, `uint`, `uint8`, `uint16`, `uint32`, `uint64`, `float32`, `float64`, `string`, `any` | None |
| `pointer` | `element` |
| `array` | `element`, nonnegative `length` |
| `slice` | `element` |
| `map` | `key`, `element` (the value type); Go validates key comparability |
| `channel` | `element`, `direction` (`both`, `send`, `receive`) |
| `function` | `signature` with required `parameters` and `results` arrays |
| `named` | `import_path`, `name`, optional recursive `type_arguments`; builtin `error` uses an empty import path |

GoML isize/usize map to int/uint; char maps to int32 and byte to uint8. Slice and MutSlice share the same Go bridge shape. Direct empty marker data maps to any; any is forbidden inside containers and multiple results. This protocol does not infer Unicode validity, readonly guarantees, or thread safety.

The response envelope contains `protocol_version`, `go_world_identity`, `referenced_types`, `bindings`, and request-level `diagnostics`. A binding result contains `binding_id`, `status`, display-only `actual_signature`, and `diagnostics`. Diagnostic fields are `code`, `message`, and optional `direction` and zero-based `index`. GoML maps binding IDs back to source spans. Statuses are `verified` and `failed`. `signature_type` references the actual signature node in `referenced_types`; display signatures never serve as type identity. The graph encodes basic, pointer, array, slice, channel, map, alias, named, struct, interface, signature, tuple, type-parameter and union nodes. Nodes use response-local IDs; fields, methods, parameters, results, type arguments, underlying types and constraints refer to those IDs. A visited table preserves cycles. Package path and object name identify named objects within the loaded Go world.

The current codec limits each message to 8 MiB, requests/responses to 4096 bindings, request bridge types to 65536 nodes and 64 nesting levels, and response referenced types to 65536 nodes. Oversized responses are rejected before writing output. The executable defaults to a two-minute timeout (`--timeout`, at most ten minutes). It closes blocked stdin when canceled, passes cancellation to the official package loader, and exits unsuccessfully for failed bindings or request errors. Active package-load cancellation and deadlines have regression tests on the Linux host. The GoML driver validates responses before treating them as success.

No persistent Verified cache is part of v1. A successful check applies only to the current Go world and caller, and does not authorize comptime or derive execution.

The executable selects the request's Go executable through an isolated temporary `go` symlink on its own PATH, without shell interpolation. It verifies the actual `GOVERSION` against `toolchain`, disables implicit toolchain downloads and workspace mode, requests readonly modules, and disables package-network lookup. The helper is a single-request host process. Its overlay adds witness functions using the requested caller loading mode; caller-directory/import-path disagreement is rejected in module mode. Existing conflicting witness files are rejected, not overwritten. GoML output staging is responsible for providing the intended fresh generated caller package during export validation.

Witness function parameters have bridge types. Results are assigned into variables with bridge result types, then returned. A unit declaration emits a call statement, preserving the existing wrapper's ability to discard Go results. Generic inference and fixed variadic argument passing use the same ordinary Go call syntax. For ordinary calls, the checker additionally rejects symbols that are not exported package-level functions. Method witnesses emit `(ReceiverType).Method(receiver, args...)` and use Go type-checker selections to record the actual method signature. This checks the real value/pointer method set, including interfaces, aliases, promoted methods and instantiated named receivers, without implicitly taking the address of a copied receiver. Methods must be exported. A nil pointer is passed unchanged; the witness does not allocate or replace it. The GoML bridge model and request encoder preserve this mode. Interface foreign-binding metadata stores method mode explicitly; absent mode decodes as ordinary for existing artifacts. Decoding rejects unknown modes, missing method receivers and package targets on methods. Equality and merge conflict checks include the call mode. GoML source `go_method` declarations lower through explicit method callables in TAST, Core, Mono and repr. Callable artifacts use the distinct `go_method` kind with a symbol and no package target. Imported methods reject invalid symbols, missing receivers and comptime capability. The backend emits a structured Go AST method expression with the same receiver type used by the witness.

The GoML consumer rejects duplicate/missing/unknown binding results, unknown statuses, inconsistent Verified results, non-signature signature references, unknown referenced-type tags, duplicate type IDs, protocol-version mismatches and oversized or excessively nested JSON. A nonzero helper exit cannot produce a successful verification result. Driver diagnostics retain binding IDs and the actual Go signature; available source spans and project-command required/off reporting are preserved.

Package compiler commands `check`, `build`, `test-check`, and `test-build` also accept `--ffi-check`, `--context`, `--caller-mode`, `--caller-directory`, `--caller-import-path`, and `--caller-package` as one complete option group. When supplied, validation runs on newly compiled binding metadata before the artifact output transaction. Partial/repeated groups are rejected. Omitting the whole group preserves the stage0 invocation contract; the project driver supplies the group explicitly and defaults to required validation.

Project drivers may add `--additional-callers <JSON-array-of-directories>` in file mode. Source publication validates every directory before writing artifacts. `gomlc __ffi-go-build --context <file> --input <Go-file> --output <executable>` performs the final readonly/offline Go file-list build with the captured context. The ordinary driver now schedules these commands and independently validates fresh artifact-cache entries. The option-group omission path remains for stage0 compiler invocation compatibility.

The artifact-check command accepts optional `--source-package <canonical-GoML-package>` and repeated `--source-path <file>` for local diagnostic provenance. Source compilation supplies its own inputs directly; Core checks also consult recorded source files when readable. Locations are associated by binding ID and attached while decoding per-binding diagnostics. These paths are not sent to the Go helper or added to interface semantic hashes.

## Internal Go library emission

`gomlc __link-go-library` accepts repeated `--input <Core artifact>`, required `--package <canonical GoML package>`, `--go-package <Go identifier>`, and `--output <Go source path>`, plus optional `--world <compiler world>`. It selects the package dependency closure, validates export metadata, installs library roots, and emits a private implementation plus public Go wrappers. Go package names must be ASCII identifiers other than keywords, `_`, or `main`.

Foreign bindings require the explicit validation option group used by package compilation: `--ffi-check`, `--context`, `--caller-mode package`, `--caller-directory`, `--caller-import-path`, and `--caller-package`. The caller package must match `--go-package`. Missing validation for a closure containing foreign bindings is an error. Validation errors occur before output writing. Closures without foreign bindings do not require Go or a context file.

This is an internal emission step, not the public `export-go` publication command. Its caller owns output staging, Go module/import-path validation, full generated-package checks, manifest creation, concurrent-output locking, and publication. Existing executable compiler/driver protocols remain unchanged.

### Export API metadata and staged package checking

`__link-go-library` optionally accepts `--api-output <path>` for a separate protocol-1 JSON document. Its `exports` array is sorted by public Go name. Each entry records `name`, stable GoML `symbol`, and `parameters`/`results` arrays using the bridge type encoding. Unit has no results and a flat tuple has multiple results. Metadata contains no absolute source origin. Both emission outputs are scratch artifacts; the caller publishes them only after complete validation.

`gomlc __check-go-library --context <path> --input <staged Go source> --directory <final package directory> --import-path <identity> --overlay <scratch JSON path>` validates a whole generated Go package. It checks module/caller identity and builds the import path with a Go overlay replacing or adding `goml_generated.go`. Existing handwritten files participate in the build. Build tags, target and Go flags come from the selected context; module writes and network lookup remain disabled. This catches stale-output masking, symbol conflicts and direct/indirect import cycles without publishing the candidate. The caller owns cleanup of the overlay and staged source.

`caller_context.generated_source` is an optional string containing candidate generated Go source. It is allowed only in package mode and overlays `goml_generated.go` in the caller directory while signature witnesses are loaded. The existing request size limit applies. Source hashing uses its contents instead of any old generated file. Export compilation/linking first use file witnesses; final `__check-go-library` accepts repeated `--core-path` and explicit `--ffi-check` to revalidate all selected Core bindings in package mode with this source overlay after the candidate Go build passes.

## Type queries

The optional `type_queries` request array and `type_results` response array extend v1 without changing requests that omit them or their responses. Each query has a unique nonempty `type_id`, `import_path`, `name` and optional `type_arguments` and `query_mode`. IDs are unique within the type-query namespace. The combined binding/query count is limited to 4096; arguments share the existing bridge-type depth/node budget. Type arguments use the bridge nodes above. Named nodes also work in helper function witnesses, preserving Go nominal types. The GoML bridge encoder emits them for resolved external identities and concrete type arguments.

`query_mode` is `instance` by default. Explicit `declaration` mode accepts no type arguments and returns declaration metadata, including generic parameters and constraints, without treating an uninstantiated generic declaration as a value type. It uses a blank-import witness and validates the requested object separately.

The helper creates a type-alias AST witness for each requested concrete type and loads it alongside function witnesses in the same packages.Load world. Type-only requests also load and validate packages. Instantiation and constraint checking use Go's type checker. Missing/private/non-type objects and invalid arguments fail with per-query diagnostics. A query-local type error does not fail an unrelated valid type query or function binding; shared package/load failures affect all dependent results.

Explicit `function` mode queries one exported package-level function named by `import_path` and `name`. Its `type_arguments` enumerate a finite concrete Go instantiation; the official checker rejects missing arguments for generic functions and constraint violations. The helper builds a Go AST variable witness referencing the function (with type arguments when supplied), loads it with the existing read-only build context, and does not execute the function or package initializers. Function variables, types, missing symbols and private functions are rejected. The public `goml bind-go` command uses this mode to discover and validate explicitly allowlisted function instances.

A type result contains `type_id`, `status`, `diagnostics`, and, when available, `declaration_kind` (`alias`, `defined`, or `function`), `declared_type` and `type`. Both type fields reference nodes in `referenced_types`. `declared_type` describes the original declaration, including its generic parameters. `type` describes the requested concrete type after alias normalization and is absent for declaration queries. For function queries, `declared_type` describes the original function signature and `type` the concrete instantiated signature, including parameter/result lists and the variadic flag. Function results are consumed separately from persisted external-type declaration metadata. A named interface is distinguishable through its structured underlying interface node. Method sets and instantiated arguments remain in the graph. These session-local node IDs are references, not portable nominal identities.

The helper exits unsuccessfully if any type result fails. Existing old helpers reject the new request field recoverably; the compiler must use its paired installed helper. Module compilation consumes this extension before typechecking `extern type` declarations and revalidates persisted instances against the current Go world.

### GoML declaration codec

`ffi::encode_type_declarations` emits declaration-only requests with unique local IDs and explicit context/caller data. `ffi::decode_type_declarations` checks bounded JSON, result completeness/status, declaration kind and requested package/name identity. It retains the structured node table after checking duplicate node IDs/fields, known tags, required references and dangling references in type arguments, members and constraints. Cyclic references remain references rather than being recursively expanded.

The retained JSON nodes are protocol data. `ffi::resolve_go_type_template` normalizes them into structured identities while preserving generic parameters and nominal types; TAST consumes the resulting descriptions. Driver orchestration schedules concrete instance queries. Host queries remain outside TAST.

Builtin Go error uses the named identity with empty import_path, name="error", and no type arguments. The helper emits the Go universe identifier error without an import. Other empty-path named identities and generic error applications are rejected. This is a real interface value, distinct from the legacy any marker; it can occur in tuple results and nested bridge shapes.

Function witnesses use the signature contract for [raw Go function values](../goml.md#raw-go-function-values). Empty parameter/result arrays represent `func()`. Children count toward the same depth and node limits; legacy marker payloads and variadic signatures are rejected. Source-level `ffi::func_from_closure` and `ffi::func_to_closure` use the same signature contract through typed callback adapters.

`source_overlay` is an optional request object with `path` and `source`. It supplies one in-memory Go file under the build module, including a file in an imported package. Paths must be clean, absolute module-contained `.go` paths and cannot use reserved witness filenames. Source is nonempty and bounded by the existing message limit. The helper applies it to the same official Go package load, hashes overlay contents for the Go-world identity, and never writes it to disk. It cannot overlap `caller_context.generated_source`. Binding generation uses a package-only placeholder to omit its previously owned output during discovery, then the full candidate to check the actual native package before publishing. Existing requests without this optional field retain their behavior.
