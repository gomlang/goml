# Callback conversion contract

This is the C0–C2 implementation contract. The public spelling below is fixed. Func, func_nil, func_is_nil and the explicit closure conversion operations are implemented. B3 deferred key checking and the remaining B4 audit are still tracked independently.

`ffi::Func[F]` denotes a nullable raw Go function with concrete GoML function signature `F`. For example, `ffi::Func[(i64) -> (i64, ffi::Error)]` uses Go `func(int64) (int64, error)`. The signature describes conversions; it does not assert that GoML closure storage is ABI-compatible with a Go func. A unit return maps to no Go results, a flat tuple return maps to separate results, and parameters retain the existing explicit boundary policies. Raw strings use `ffi::String`; no implicit Unicode decoding is added.

The public operations are `func_nil[F]() -> Func[F]`, `func_is_nil[F](value: Func[F]) -> bool`, `func_from_closure[F](value: F) -> Func[F]` and `func_to_closure[F](value: Func[F]) -> Option[F]`. The type checker must require a function signature for F and validate every parameter/result boundary. Raw functions are not directly callable as GoML closures. Conversion from nil returns None, while conversion from a GoML closure produces a non-nil Go function. Source closures continue through lambda lifting.

Closure-to-Go conversion records a typed adapter requirement beside the existing environment/apply/signature representation. A generated typed method value or thunk holds the closure environment strongly. Reverse conversion holds the original Go function in a closure environment and invokes it through a typed apply function. There is no reflection, global dispatcher, handle registry, implicit panic recovery or global FFI lock. The adapter records must survive artifacts, specialization and DCE, including captures reachable only through a callback.

The helper protocol represents a function as `{"tag":"function","signature":{"parameters":[...],"results":[...]}}`. Both arrays are required, including empty arrays for `func()`. Every child contributes to the existing depth/node budgets. Nested function signatures are structural types and use the same Go witness compiler as ordinary values. Legacy `any` marker payloads and variadic signatures are not accepted by this protocol shape. Existing protocol v1 shapes remain unchanged.

C0 acceptance requires uncaptured and captured closures, shared mutable cells, distinct closures with the same signature, unit and multiple returns, returned Go functions and nil conversion. C1 adds retained/asynchronous callbacks, explicit unregister, recursion/reentry, concurrent goroutines and race tests. C2 adds same-goroutine panic propagation, source provenance, stable output, installation/bootstrap and measured performance. GC reachability does not replace explicit resource unregistration, and tests must not depend on prompt finalization.

The GoML bridge model now carries separate ordered parameter/result lists, emits the same signature object and preserves it in interface metadata and persisted type-instance arguments. Function identity keys keep those lists separate, and generic substitutions traverse both. Go metadata aliases to non-variadic function types normalize to this structural identity. Raw GoML function values now have a distinct GoFunction IR type and normalize supported external function aliases. Runtime conversions now use typed adapter requirements carried as repr::Callable::CallbackAdapter through Lift and ANF. Go emission creates a signature-specific holder struct and Apply method, and the factory returns a bound method value. The public reverse adapter checks nil before constructing the closure. Lift/ANF validate conversion direction, signature and raw text policy. Source artifacts retain the intrinsic request until concrete specialization produces the adapter. Async/reentry/concurrency are covered by the retained subscription example below. C2 acceptance evidence is recorded in [acceptance-c2.md](acceptance-c2.md).

## Retention and subscription example

examples/ffi-callbacks now exercises a retained closure after its creating function and Start call return, with a GC before dispatch. A gate releases 64 concurrent goroutines; captured immutable values and an atomic Go Counter remain valid. Recursive reentry crosses the boundary 32 times, and a callback unregisters itself without a held subscription or global FFI lock. Queued and new batches dispatch no callbacks after unregister. Already selected invocations may still run; Wait joins each batch before captured resources are discarded. Registration accounting balances after 128 additional cycles. The committed example is exercised fresh, cached and under go run -race by the driver regression.

## Panic propagation and pruning

The callback panic regression verifies original Go panic object identity after Go→GoML→Go calls and after a Go function is converted to a GoML closure and back. Explicit Go defer/recover test adapters observe the original object; deferred Go work completes during unwinding. Unit and multi-result adapters do not synthesize successful values or errors. A nil-map write inside a GoML callback preserves its native runtime panic. Unhandled synchronous and asynchronous callbacks fail their processes with the original panic message; no cross-goroutine recovery is implied.

The captured state and its private helper live in another GoML package and remain callable when their only live path is the callback. An unrelated private helper is absent from generated Go, verifying that the fixture actually undergoes pruning. Fresh and cached runs preserve behavior and identical generated source. This is runtime reachability evidence for these paths, separate from the source-provenance checks below.

[The callback benchmark](../../examples/ffi-callback-bench/README.md) measures native and adapted invocation and escaping callback creation separately. Results are observations for the recorded toolchain and machine, not portable performance guarantees or CI thresholds.

## Persisted source provenance

Core artifacts now preserve source origins for package-level GoML functions, extern bindings and explicitly defined impl methods: canonical symbol, package-relative file name, byte range and one-based line/Unicode-column position of the declared name. Origins are collected from the same source text used for parsing, sorted by symbol and stored independently of interface semantic hashes. They remain available when the original source file is absent. The Core decoder rejects duplicate or foreign-package function symbols, invalid ranges and non-relative file names. Method identities must refer to an actual inherent or trait implementation function in that Core unit. Core JSON format 28 and binary value-section version 8 require artifacts produced within the current bootstrap stage.

Executable, test and library module links now embed a versioned JSON origin index in the generated Go string constant `_goml_source_origins`. Monomorphization records each specialized name's original symbol; lambda lifting records the enclosing function for generated apply functions, including nested closures. The backend maps surviving generated functions and referenced callback factories/Apply methods to those records. Shared signature adapters carry multiple entries. External-call wrappers map to their enclosing caller declarations and the actual extern bindings used by those calls. Callable metadata carries the binding identity through specialization and artifacts; wrapper names still depend on the native target and specialized signature. Shared wrappers can therefore identify several used bindings without attributing unused aliases of the same target. Finer expression/line-table mapping is outside this declaration-level index. Synthetic methods without an original declaration span are omitted.


The embedded index has `version: 1`, `scope: "enclosing-declaration"` and an `entries` array. Each entry contains `generated_symbol`, `source_symbol`, `source_package`, `source_file`, `start`, `end`, `line` and `column`. Ordinary functions use their generated Go name; callback methods use `ReceiverType.Apply`. Source files are relative to the canonical source package, and positions identify its enclosing declaration name rather than the exact callback expression. Read the constant as a Go string literal before decoding its JSON. Entries are sorted and duplicate generated/source pairs are removed. The constant is added after Go declaration pruning and travels with the normal generated source/cache output. It does not install a runtime registration table or change panic recovery.

The driver regression parses the generated program with Go's AST parser, checks every indexed symbol against a real function/method declaration, validates source byte ranges and line/column positions, verifies multiple origins for one shared callback method, and checks generic nested closure ownership. A dead helper produces no mapping. Fresh/cached source equality includes the embedded index.

Internal and black-box test links also embed the same origin index. Their test declarations and nested callback environments retain canonical package identities. The regression validates the executable and both test runners independently with Go AST/source-coordinate checks, and compares first/cached output for each runner. The test manifest and generated source retain their existing transactional output contract.

Go library exports embed the same index after private-name rewriting. The rewrite stage returns its actual collision-resolved replacements; indexed internal functions and callback owners use those names. Public export wrapper names also map to their selected GoML declaration. A normal Go caller and AST validation exercise exported code containing generic nested callbacks, and repeated export produces identical source. The index remains an unexported constant and adds no public Go API.

Explicit impl methods use Core's receiver/trait-qualified identity, including generic type parameters, rather than their bare method name. The additive `source_package` field identifies the package containing the declaration independently of types or traits mentioned by that identity. TAST retains the declaration-name span, and Mono records trait method renaming during type materialization as well as specialization. Lifted capture environments can therefore be traced to distinct same-named methods. Shared adapters retain the enclosing generated caller associations when bodies are inlined; the index does not claim exact expression-level inlining history.

Ordinary extern calls and `go_method` calls preserve their declaration identity in the optional callable `id` field. Legacy callable bodies without that field decode with no binding origin; malformed non-string IDs produce recoverable diagnostics. The regression covers two used declarations sharing one native wrapper, unused declarations targeting the same symbol, distinct string/raw-string signatures and receiver-method bindings across program, test and library output.
