# D2 allowlist generator acceptance audit

Status: accepted. Full CI passed with 895 compiler tests, 154 driver tests, helper race checks, stage3 fixed point, extension compilation and extracted-release/LSP smoke, including the new bind-go example.

| Plan requirement | Implementation and evidence |
| --- | --- |
| Independent command using shared metadata | `goml bind-go` resolves the compiler through the existing driver protocol and forwards to `gomlc bind-go`. Compiler orchestration uses `bind_go`, the shared FFI codecs and the existing Go helper. There is no second Go parser. |
| Explicit package/symbol allowlist | The bounded versioned JSON parser accepts individual exported native symbols and distinct GoML binding names, rejecting unknown/duplicate fields and invalid identifiers. It neither imports an entire package nor infers additional bindings. |
| Finite generic arguments checked by Go | Function and type-instance queries preserve explicit bridge-type arguments and verify instantiated signatures. The CLI Numeric[int64] test checks/runs the generated aliases and wrappers; substituting string fails before publication and preserves both old files. The Sum[int64] variadic test executes an explicit slice expansion. |
| Explicit raw boundaries | Generated GoML signatures use ffi::String, ffi::Error, raw pointers/slices/maps/functions and named allowlisted types. The standard-library example makes text conversion and error inspection explicit. No implicit error, nullable or record adapter is generated. |
| Correct caller and native package behavior | Temporary queries run below the native output directory. CLI tests cover permitted deep internal imports, forbidden outside callers and preexisting query-directory preservation. Same-package generic functions/types use unqualified names. A module-contained in-memory source overlay omits old owned wrappers during discovery; full candidates are checked in the actual native package before publication. Tests cover stale signatures, duplicate symbols, type-only package conflicts and candidate-induced import cycles. |
| No initializer execution or dependency mutation | Helper and CLI fixtures contain panic initializers that would fail if executed. The helper only loads/typechecks Go packages, with readonly dependencies and network off. Standard-library command tests retain go.mod bytes and create no go.sum. |
| Deterministic and protected publication | The publisher verifies both source hashes against one canonical ownership manifest, serializes generators, checks for changes during generation and stages both files plus the manifest. Identical generation preserves timestamps; manual edits and incomplete/unowned outputs are refused. Rollback tests force failure after both source commits and cover new and existing outputs. |
| Reviewable complete example | `examples/ffi-bind-go` includes the input configuration, generated sources/manifest and handwritten main. Actual generation, formatting, check and run passed with output 3/42/true. It uses strings.Count and strconv.Atoi; no third-party version is needed. |
| Packaged-toolchain behavior | The release smoke script copies only the example's input files, generates using the extracted tools, repeats and compares digests, checks/runs the output and verifies manual-edit refusal. This smoke path passed in the complete CI recorded below. |
